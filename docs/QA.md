# QA

What was checked, how to run each check again, what the last run found, and what was not checked. Every figure comes from one machine (see `docs/COMPATIBILITY.md`) on 2026-11-15, unless a row says otherwise.

## Run the checks

| Command | Needs | Checks |
| --- | --- | --- |
| `npm run typecheck` | | TypeScript compiles in strict mode |
| `npm test` | | the unit tests listed below |
| `npm run build` | | typecheck, then the production build |
| `npm run smoke:dist` | `npm run build` | serves `dist/` under a sub-path, the way GitHub Pages does. The game starts without a click, the canvas draws, the splat count is reported, nothing logs an error or warning and nothing answers 4xx or 5xx. `--browser chrome`, `firefox` or `webkit` picks the engine |
| `node scripts/qa/smoke-dist.mjs --file dist/reality-origami.html` | `npm run build:single` | the same checks on the single file opened from disk with no server, and it fails on any request that is not `file:`, `data:` or `blob:` |
| `npm run smoke` | | plays the page for 16 steps: walk, jump, glide, fly, each power, help, photo mode, a larger window and a smaller one. It saves a screenshot and the frame rate of every step, and any console error fails the run. `npm run smoke -- --browser firefox` or `webkit` plays it in another engine |
| `node scripts/qa/terrain-probe.mjs` | `npm run dev` | the GPU terrain against its CPU twin at 4,000 random points out to 40 km |
| `node scripts/qa/audio-check.mjs` | | renders eleven scenes of the score offline, thunder included. Nothing clips, nothing is silent, each realm has its own level and brightness, and the wind opens with speed |
| `node scripts/qa/splat-census.mjs` | | how many splats a frame really draws, per realm and per layer. It serves the source itself, or reads a build with `--base` |
| `node scripts/qa/field-cache.mjs` | `npm run preview` | the cached cell fields against fresh fills while standing, walking, running, flying, teleporting and switching worlds. It counts the fills per frame and fails on any texel that differs |
| `node scripts/qa/benchmark.mjs` | `npm run preview` | frame times in scripted phases. `docs/BENCHMARKS.md` has the method and the results |
| `node scripts/qa/stage-cost.mjs` | `npm run preview` | the drained cost of a frame as the layers, the sky pass, the cell field passes and the resolve are switched off one after another |
| `node scripts/qa/saturated.mjs layers\|cull\|detail\|idle` | | what one part costs, with vsync and the frame limit off and the states flipped inside one run. `layers` hides each splat layer, `cull` turns the view cull off, `detail` steps the ground detail levels and `idle` adds slots that all decline. It serves the source itself and prints the load average before and after |
| `node scripts/qa/game-shots.mjs` | | photographs the live game from 19 fixed poses, with the HUD hidden and the clock frozen. It serves the source itself. Two runs of the same code give the same frames, and `index.json` holds a hash per pose. `--browser firefox` or `webkit` photographs them in another engine, to compare against Chrome's frames |
| `node scripts/qa/touch-smoke.mjs` | | plays the page as a touch phone, portrait (390×844) and landscape (844×390), at a device pixel ratio of 3. Every gesture is a real touch event sent through the DevTools protocol. Checks that the controls fit the screen and clear one another, that the left half walks, that the right half turns, that the jump button leaves the ground and that a tap on the planet button switches it on and off. It saves a screenshot per step |
| `node scripts/qa/steady.mjs` | | walks each realm for 240 frames on a clock that moves 1/60 s a frame, reads the framebuffer after each one and fails when the mean brightness jumps by more than 0.04 between two frames, or when the walker moved less than half the way the keys carry it. It opens the page with `calm`, which turns the lightning off, because a bolt is a flash on purpose (the first version read one in Ember as a jump of 0.106). `--keys ShiftLeft,KeyW` runs, and then wants a higher `--limit`. It serves the source itself, and `--browser` picks the engine |
| `node scripts/qa/soak.mjs` | | plays the page for five minutes with the HUD hidden: run, fly and warp, each power, a sung ring, a photo and a jump to a new world, round after round. Every 20 s it forces a garbage collection and reads the heap and the number of textures, geometries and shader programs that three.js holds. It fails when the heap climbs by more than 0.25 MB a minute after the first minute, when any of the three counts rises after that minute, when the console logs an error or a warning, or when the walker covered less than 100 m or never left its first world. It serves the source itself and drives Chrome only |
| `node scripts/qa/cold-start.mjs` | `npm run build` | times a build from the request to the first splats on screen, once with a cold shader cache and once with a warm one in the same browser. A browser and the operating system keep every shader they have compiled, so a plain run is always a second visit. Each cold run serves a copy of the build with a number nobody has compiled added to the lighting code. It prints the time to the first splats, the time until the loading box hides and the longest task that held the page. `--dist`, `--runs`, `--size` and `--browser` are the options. Compare two builds by running it on each in turn |
| `node scripts/qa/shader-cost.mjs` | | builds the shader program of each layer alone, in a blank page of the same browser and with a source nobody has compiled, and prints how long the link and the first draw took. Layers that share a program share a row. Read it when a first visit is slow and after adding a layer or a wonder. It serves the source itself, and `--browser` picks the engine |
| `node scripts/qa/encodable.mjs` | | runs every layer's generator for every splat slot with the view cull off, in each realm and under every combination of the three fold powers, and fails when a live splat has a correlation closer than 1e-4 to 1 or a shape that is not finite. Firefox reads such a splat back as a blob, see `docs/COMPATIBILITY.md`. `--browser` picks the engine |
| `node scripts/qa/ab-cost.mjs --a dirA --b dirB --control` | two builds | the drained frame cost of two builds, interleaved, with a second run of the first build as the noise floor. It prints the splat count of each build |
| `node scripts/qa/blur-brightness.mjs` | `npm run dev` | a film frame has the same mean brightness from one sub-frame and from four |
| `node scripts/qa/av-sync.mjs out/reality-origami-1080p.mp4` | the encoded film | the gap in frames between the sound's attack and the picture's flash at every impact in the cue sheet |
| `node scripts/qa/compare-encodes.mjs a.mp4 b.mp4` | two encodes of the same frames | PSNR and SSIM of one against the other |

CI (`.github/workflows/ci.yml`) runs the type check, the unit tests and the build on Node 22. It runs no browser check.

## What the unit tests cover

| File | Tests | Covers |
| --- | --- | --- |
| `tests/deform.test.ts` | 23 | the reference fold maths against finite differences, stage by stage and composed, the curve table, covariance transport and the validity limit |
| `tests/folds.test.ts` | 5 | the powers as the page sets them. Nothing changes when none is on, all combinations stay finite far away and high up, the planet never turns the ground inside out, the fold does not stretch the ground, and twist and ripple keep volume |
| `tests/world.test.ts` | 19 | the CPU terrain, wonders, creatures, spawn and share links |
| `tests/player.test.ts` | 3 | flight. A climb is free below the easing height, stops at the ceiling even at warp speed, and a descent works from the ceiling |
| `tests/storm.test.ts` | 7 | the lightning schedule. The same clock gives the same flash and another seed another, strength sets the share of slots that hold one, every stroke ends inside its slot, a stroke flares at once and fades, a flash flickers, and an empty slot gives none |
| `tests/rings.test.ts` | 9 | the rings of light. A ring shines at full strength for two fifths of its life and is out at the end, a new ring takes the slot with the least light left, a footstep fades out before its slot is wanted again at a stroll, a walk and a run, and the world uniform packs each ring into its slot, clears the others and refuses more rings than the shaders draw |
| `tests/film.test.ts` | 23 | the cue sheet, the cut, the camera on every frame, the director, the motion blur sample counts, and the two strokes of lightning, which fall in the Ember shot on beats of the track, in front of the camera, and nowhere else |
| `tests/assets.test.ts` | 5 | the source tree holds no model, texture, image, font or sound file, loads nothing at run time, depends on three and Spark only, and keeps the track out |
| `tests/cull.test.ts` | 9 | the view cull. No point on the screen is culled at random cameras, a splat whose body reaches into view is kept, what lies behind the camera or far to the side is culled, a larger radius culls less, a view too wide to be a wedge is never culled, the planes are written into the cull it is given, the uniforms the shaders read carry the planes, the slack and the reach per metre, a frame without a view skips nothing, a fold turns off the early cull of the ground, and only a world with no fold counts as the identity |
| `tests/detail.test.ts` | 4 | the ground detail levels. Level 0 keeps every splat, a coarser level never draws more and never fewer than one per facet, the coarsest takes more than half away, and the render scale picks a level that never falls as the scale does |
| `tests/lens.test.ts` | 5 | the lens. A window as wide as it is tall keeps its field of view, a taller one holds the horizontal field of a square window until the vertical field reaches 100 degrees, and the field never narrows as the window gets taller |
| `tests/governor.test.ts` | 10 | the resolution governor holds on time, steps down when slow, ignores one long stall but not a run of long frames, stops at its floor, remembers a scale that failed, judges a 120 Hz display against 120 Hz, and honours a lock |
| `tests/input.test.ts` | 5 | the name of a key. The walking cluster and the number row go by position, so ZQSD on a French keyboard walks and a power starts while Shift is held, no letter shortcut takes a walking key on another layout, every other key goes by its letter, and an event with no code falls back to the letter |
| `tests/programs.test.ts` | 3 | the shader programs Spark builds for the layers, with the accumulator flags the page uses. A water mirror gets the text of the program of the layer it copies, the four size classes of flora get one program, and flora and wonders get different ones, so the comparison cannot pass by returning the same text for everything |

Some tests were checked by breaking the code on purpose. Setting `HINGE_SPAN` to 40 and `PLANET_RADIUS` to 12 each failed exactly the intended test in `tests/folds.test.ts`. In the governor, a drop threshold of 50 s, a failure memory of 0 s and an ignored lock each failed the tests that name them. Taking the stall cap out failed the stall test alone, and a cap of 5 ms failed seven tests.

## Not verified

- **Other hardware.** Everything ran on one Apple M1 Max. Chrome with ANGLE Metal took every timing. Firefox and WebKit, in the builds Playwright ships, drew the 19 poses and played the smoke test on the same GPU. No Windows, Linux, Safari app, discrete GPU, integrated Intel GPU, phone or tablet. Engines on one GPU agree more easily than different GPUs would.
- **A first visit anywhere but one Mac.** The cold start was timed in Chrome, WebKit and Firefox on the M1 Max. Windows builds a program through D3D11 and its HLSL compiler, which may take longer than Metal does. The kick-off in `compileShaders` should help there at least as much, because it lets the links overlap (inferred, not measured). A phone was not timed either. Firefox still takes 12.5 s. The Firefox that Playwright ships lists no `KHR_parallel_shader_compile`, so its links cannot overlap (measured with `getSupportedExtensions`, and an inference for the time).
- **A quiet machine.** All frame times were taken while other work kept the one-minute load average between 12 and 366 on 10 cores.
- **Headroom above 60 fps.** Headless Chrome ticks at 60 Hz. The drained cost of a standing frame suggests at least 5.5 to 7.5 ms of room in a 16.7 ms tick, and no run used a display that ticks faster.
- **A real window.** No run used a real Retina panel or a 120 Hz display. A device pixel ratio of 2 was emulated once on a 1440×900 window (`play-smoke.mjs --dpr 2`, measured). There were no console errors and the page read 60 fps at 13 of 16 steps, 58 at two and 40 in the first second after the help panel opened. With the panel open for three seconds and the world frozen, the frame gaps read a 95th percentile of 16.7 ms, the same as with it shut and with every backdrop blur turned off. The governor chose render sizes of 1253×783 to 1469×918 under its cap of 1.5.
- **A hidden tab.** The stall cap in the governor was checked with a unit test and a 3 s block of the main thread. No run hid a tab.
- **The shader against the reference.** No test compares `deform.glsl` with `src/core/deform`. The stills and the film are the evidence.
- **Combined powers.** The tests pin each power alone and finiteness in combination. Twist with fold and planet with twist can fold the world through itself, and no test says what that should look like.
- **The mouse and a real phone.** `scripts/qa/touch-smoke.mjs` plays an emulated phone in Chrome on the Mac. No real phone was used, and no script drives the mouse (pointer lock and drag look). The play smoke test uses the keyboard.
- **Events.** The gate ripple, a share link copied with `G`, a jump to another world with `N` and saving a photo have no script.
- **Long sessions.** `scripts/qa/soak.mjs` played five minutes at 960×540 through 8 worlds. The JavaScript heap stayed between 16.1 and 16.6 MB after a forced collection every 20 s, a slope of −0.02 MB a minute after the first minute. three.js held 43 textures, 3 geometries and 18 programs from the first minute to the end (one texture and one program appeared between the first sample and the second), and the console stayed quiet (measured). A leak of 10 KB a second, planted in a copy of the script, read as 0.62 MB a minute and failed the run. The memory of the GPU, a session of an hour and thermal throttling are unmeasured.
- **Sound.** The checks measure level and brightness. Nobody listened to the score or to the film's mix.
- **Taste.** One reviewer looked at the film and the page. There was no second pair of eyes.
- **Node 22.** CI asks for it. Only Node 26.13.1 ran the tests.
- **A real deployment.** The Pages workflow has never run, and the repository has no remote. The dist smoke test serves `dist/` under a sub-path on this machine.
- **The soundtrack's licence.** The track is not in the repository. It looks like a Pixabay track, and the licence text was not read.
